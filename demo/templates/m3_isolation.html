03.1 / CONTROLES DO RESOURCE SERVER · HTTP REAL

A API MagaluPay confia no emissor certo — e rejeita o errado.

Dois JWTs são verificados pela mesma API. O token válido do próprio MagaluPay deve ser aceito; o JWT do Commerce deve ser rejeitado. Um erro de formato (HTTP 422) nunca conta como isolamento.

CONTROLE POSITIVO · TOKEN MAGALUPAY PENDENTE Aguardando prova OAuth. Assinatura · Issuer · Audience: —
CONTROLE NEGATIVO · TOKEN COMMERCE PENDENTE Aguardando prova OAuth. Rejeição por identidade de tenant: —

Nenhum aceite presumido: a prova depende de HTTP 200 (token MagaluPay), HTTP 401 (token Commerce) e validação de issuer/audience no resource server.
